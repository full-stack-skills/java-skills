# 深度 FAQ

## 1. 不同维护线使用不同 Maven 主版本怎么办？

把 Maven 版本和命令作为证据身份的一部分。不要用 Maven 3 的通过替代要求 Maven 4 的分支；模型警告与构建失败分开记录。

## 2. 多线共享本地 Maven 仓库是否安全？

常规回归可以共享，但它不能证明远端制品可消费。若门禁涉及发布可用性，应增加隔离空缓存解析；许可证/SBOM 证据也应能追溯到各线解析出的精确版本。

## 3. SBOM 文件没有变化，还要重新生成吗？

要。重新生成用于证明它来自最终 SHA 和当前依赖图；可以用哈希相同证明结果稳定，但不能只沿用旧文件时间戳。

## 4. 上游许可证页面会变化怎么办？

优先引用版本标签、固定提交、版本 POM 或不可变仓库对象，并记录校验时间。只有可变主页时，保存可审计的来源身份或按组织政策归档。

## 5. 依赖未直接使用，是否一定可以排除？

不一定。先检查编译引用、运行时加载、SPI、反射和集成测试；排除后用依赖树、契约/集成测试和 SBOM 一起验证。

## 6. CI job 被 cancelled 后重跑成功可以吗？

如果重跑对应同一最终 SHA、配置未变且组织政策接受重跑，可以用成功的最终 run 闭合；保留 cancelled run 及原因，不将其抹去。

## 7. 分支保护显示通过，但找不到 head SHA 怎么办？

状态标 `unknown`。通过 run API、commit checks 或 UI 详情补齐 head SHA；不能仅凭绿色图标推断属于当前提交。

## 8. 组织新增了一个必需检查怎么办？

重新读取当前分支保护/发布政策并更新矩阵。若新检查适用于当前目标 SHA，等待它完成；不要沿用任务开始时的旧清单。

## 9. 如何自定义组织门禁？

在矩阵增加列，并为该列定义状态枚举、必需证据、通过条件、是否阻断和授权豁免规则。不要改变 `passed` 的含义。

## 10. 时间窗口结束但 CI 未完成怎么办？

交付 `partial` 状态：列出已冻结 SHA、已闭合门禁、仍运行的 job、最近观察时间和后续等待动作。时间压力不改变门禁。
