# 反模式与改进

## 1. 用可访问性替代许可证语义

错误：URL 返回 HTTP 200，因此许可证证据通过。

改进：记录精确 GAV，检查响应内容是否是对应版本的 POM、LICENSE 或官方元数据，并确认其中语义支持结论。

## 2. 拼接局部成功

错误：完整 Reactor 在模块 X 失败，X 单独通过，所以整个 Reactor 通过。

改进：优先重新执行完整 Reactor。仅在能证明失败前模块、恢复点和剩余模块覆盖，且源码、SHA、工具链、参数均未变化时，采用可审计的 `-rf` 链。

## 3. 把过程状态写成终态

错误：push 成功、CI 已启动、暂时没有失败，因此宣布完成。

改进：分别记录 `remote_sha_matched=passed` 与 `required_ci=in_progress`；仅最终 conclusion `success` 闭合 CI。

## 4. 跨分支借证据

错误：同一脚本在新分支通过，旧分支自然也通过。

改进：脚本可以比较内容复用，但每条线必须按其工具链、依赖图、POM 拓扑和最终 SHA 独立验证。

## 5. 跨 SHA 借证据

错误：旧 SHA 生成的 SBOM 加新 SHA 的 CI 构成一套证据。

改进：任何影响依赖、策略、生成物或测试范围的提交都使相关旧证据失效；矩阵绑定最终 SHA。

## 6. 用豁免伪装通过

错误：安全或许可证检查未执行，但总结为“全部绿”。

改进：使用 `skipped`，记录谁授权、为什么、期限和残余风险。若它仍是必需门禁，整体不能 `passed`。

## 隐私与安全

- 日志和报告分享前删除 token、HTTP Authorization header、仓库凭据、带凭据的仓库 URL、私有下载 URL 查询参数、环境变量、用户名和内部主机名。
- 不展示 Maven `settings.xml` 中的 server 凭据、签名私钥内容或可识别私钥位置的敏感路径。
- 不把真实密钥写入 Skill、命令示例、CI 评论或持久化报告。
- 远端变更只作用于用户明确指定的仓库、分支和 workflow；不操作他人账号或无授权组织。
- 原始证据需要保留时，优先引用受控路径或 run URL，不在对话中大段复制敏感日志。
